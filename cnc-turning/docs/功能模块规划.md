| 资产 | 位置 | 车削复用度 | 实测事实 |
|---|---|---|---|
| 单文件架构 | `app.html` | 直接复用 | 1.47 MB，零依赖零构建 |

## 2. 车削与铣削的七个本质差异

| # | 差异 | 对模块的影响 |
|---|---|---|
| 1 | **X 轴按直径编程**，图样 Φ50 就写 X50 | 轨迹图需直径/半径双刻度；校验要抓"写 X25"这种报废级错误 |
| 2 | **G50 双含义**：设工件坐标系 / 限主轴最高转速 | 解释器与校验器靠上下文判意图 |
| 3 | **复合循环是主体**（G71/G72/G73/G76 都是 P/Q 块） | 解释器整块翻译；校验器查 P/Q 存在性·顺序·一致性 |
| 4 | **刀尖半径补偿靠方位号** T1~T9 | 刀补独立成体系；需要"方位号判定器"这种交互工具 |
| 5 | **轨迹是开放路径** | 轨迹引擎变简单，但"余量/材料去除"视图更重要 |
| 6 | **进给 mm/r**，恒线速下 n 随直径变 | 参数计算与螺纹强耦合（F = P×n），按最大直径核算转速上限 |
| 7 | **毛坯是棒料** | 可做毛坯剖面，逐层看粗车余量——车削独有的教学抓手 |

## 2.5 车削校验的输入契约（v0.1 最大漏洞）

**问题**：铣削的 `lintProgram(text, opt)` 只收 `{pitch, nmax}`，因为铣削 43 条规则几乎都能从程序文本自证。车削不是——50 条里 **12 条必须知道程序之外的事**：

| 缺什么 | 就判不了什么 |
|---|---|
| 毛坯直径 Φ | X 是否按半径写（P04）、单刀切深是否过大（P08）、精车余量是否合理（D01） |
| 夹持长度 | Z 是否撞卡盘（S02/P05） |
| 材料 | vc 是否超上限（P03）、F 是否超范围（P07） |
| 刀具库（R / 刀宽 / 方位号 / 刀补表） | 刀补方向是否冲突（T04）、切槽能否切净（D03）、刀补号是否超表（S06） |
| 螺纹公称与螺距 | F 是否等于螺距（M02）、退刀槽是否够（M04） |
| 零件总长 | 切断位置是否正确（D02） |

**如果不管这条**，只有两条路，两条都错：

- 让规则去"猜"（从程序里的最大 X 反推毛坯）→ **假阳性**，冤枉学生，工具失去信任
- 判不了就跳过 → **假阴性**，报废级错误静默放过，比假阳性危险得多

**所以新增 G1「工件卡」——全局工艺上下文**，不是面板，是常驻状态：

```js
G1 = {
  blank: { d: 50, len: 80 },      // 毛坯 Φ × 长
  clamp: 25,                      // 卡盘夹持长度
  material: '45钢',
  part:   { len: 60 },            // 零件总长
  thread: { nominal: 30, pitch: 1.5, type: 'M' },
  tool:   'T0101'                 // 当前工序刀具（取自刀具库）
}
```

三条硬规矩：

1. **每条规则声明 `needs: ['blank.d', 'clamp']`**，字段缺失时规则进入 `NA`（无法判定）状态，不报通过、不报错误。
2. **UI 必须显式列出"未判定项 N 条"**，并给一键跳转到工件卡填字段。绝不静默通过。
3. **工件卡存 localStorage，随程序一起导出**（JSON 尾注），批改时可批量导入——否则批改的判定口径和学生自检不一致。

## 4. 面板清单 v0.2（10 个）

### P0 · 走通一次作业（M1–M2）

**1｜G/M 代码速查**
车削指令全集：G 42 条 + M 12 条 = 54 条（M0 已落地）。**双含义指令单列**（G50 两种用法、G90 既是绝对编程又是外圆循环），提示卡说明"本系统按哪个理解"。

**2｜程序编辑器（编辑器 + 模板 + 生成器）**
- 模板 10 个：骨架 / 车端面 / G90 单一循环 / G71+G70（含 C·R 倒角）/ G73 仿形 / G75 切槽+切断 / G92 螺纹分层 / G76 螺纹复合 / 内孔 / 综合件
- 快捷片段 12~14 条（G71 两行、G76 两行、G75、倒角、G96+G50）
- **生成器页签**（原面板 10）：尺寸表 → 轮廓 → G71+G70 程序，产出直接落进编辑区，可再手改；这是唯一"往编辑区写程序"的通道，避免两套生成口径

**3｜参数计算**
vc / n / f / ap 四联算 + 螺纹计算器 + 切槽扩槽计算，全部读 G1 工件卡与刀具库，不各自维护默认值。
- 恒线速 `n = 1000·vc/(π·D)`，按**最大直径**核算，超机床上限直接提示应设的 `G50 S___`
- 螺纹：牙高 `h≈0.6495P`、小径 `d−1.3P`、分刀表（每刀 ap 递减）
- 切槽：刀宽 × 槽宽 → 扩槽次数与每次 Z 位移

**4｜程序解释**
逐行翻译 + **循环块整块翻译**。`U` 的三种含义（G71 第一行切深 / 第二行直径余量 / G01 增量）是本面板的核心难点，按上下文取值并标注单位。

**5｜程序校验**
50 条规则，S/E/W/I 四级，每条 `why + fix`；顶部显示「已判定 N / 未判定 M」，未判定项可一键补工件卡。

**6｜刀轨演示**
ZX 轨迹、分步、代码双向联动、尺寸核对；左侧 X 轴**直径/半径双刻度**（可切）；刀尖 R 放大示意讲清"端面为什么留凸台"；G71 余量分层着色。

### P1 · 练与教（M3）

**7｜批量批改**：多份 `.nc` + 各自工件卡 → 打分（E6 口径）+ 问题清单 + 轨迹对比 + CSV；内置 4 份演示作业（满分 / 漏 G50 / X 写半径 / 余量 0）
**8｜找错练习**：10 种车削变异注入 + 交卷对答案，每种变异必须被指定规则命中（断言）
**9｜刀具与对刀**（原「刀具库」升级）
- 刀具表：T 号 / 类型（外圆·端面·内孔·切槽·切断·螺纹·钻）/ 刀尖 R / **刀尖方位号 T1–T9** / 刀杆截面
- **试切对刀计算器**：量得 Φd → X 刀补 = d；端面轻切 → Z 刀补 = 0
- **方位号判定器**：选刀型 + 走刀方向 → 输出方位号与应配的 G41/G42（学生最易错点的交互化解法）
- 刀补表填写练习：给图与测量值，填 X/Z 磨损与几何补偿

### P2 · 收口（M4）

**10｜帮助**：内嵌说明书 + 目录 + 检索，由 `docs/使用说明.md` 单向生成；**配图一律内联 SVG 线稿，禁止嵌 PNG base64**（理由见 §7）

## 5. 校验规则 v0.2（50 条 / 四级 / 带依赖声明）

### 5.1 四个级别

| 级 | 含义 | 行为 |
|---|---|---|
| **S** | 会撞刀或直接报废 | 阻断：不给分、不生成程序、红条置顶 |
| **E** | 程序跑不到预期结果 | 扣分，允许继续 |
| **W** | 隐患，可能出错 | 扣少量分，提示 |
| **I** | 教学提示 | 不计分 |

v0.1 只有 E/W/I 三级，表达不了"这条必须拦住"——这是 A5 问题。

### 5.2 分组与依赖

| 组 | 条数 | 其中 S | 需要的上下文 |
|---|---|---|---|
| S 结构 | 9 | 1 | 无（O 号 / M30 / G21 / G99 / 坐标系 / T 四位 / T 与刀补号 / M30 后语句 / 重复 O 号） |
| C 循环 | 15 | 2 | 无（P/Q 全在程序内；G71 两行 U 语义、G76 位数、G74/G75 方向、模态残留） |
| T 刀补 | 7 | 2 | 刀具库（刀尖 R、方位号、刀补表条目） |
| M 螺纹 | 7 | 0 | 螺纹规格（公称、螺距） |
| P 参数安全 | 8 | 0 | 毛坯 Φ、夹持长、材料、刀具 R |
| D 尺寸 | 4 | 0 | 零件总长、槽宽、刀宽 |
| **合计** | **50** | **5** | 12 条需上下文（23%） |

### 5.3 五条 S 级（必须拦住）

| 编号 | 规则 | 一句话 |
|---|---|---|
| S01 | X 值疑似按半径编程 | 图样 Φ50 写 X25，加工出 Φ25，直径小一半 |
| S02 | Z 向进入夹持区 | 撞卡盘，工件与刀具一起报废 |
| S03 | G71/G72/G73 的 P 段或 Q 段不存在 | 系统报警，程序根本执行不下去 |
| S04 | G76 第一行参数位数不对 | `P(m)(r)(a)` 共 6 位，少一位牙型角就错 |
| S06 | 刀补号超刀补表条目 | 按 D0 处理，轮廓整体小一个半径 |

### 5.4 三条教学文案（写成学生的两句话）

**S01｜X 值疑似按半径编程**
> why：本机床 X 轴按**直径**编程，图样 Φ50 应写 X50。写成 X25 系统会按 Φ25 加工，直径小一半。
> fix：核对图样标注，把 X 改成直径值；确需半径编程先改系统参数 No.1006#3。

**C05｜G71 两行里的 U 不是一回事**
> why：第一行 `U2` 是每刀切深（半径值），第二行 `U0.5` 是 X 向精车余量（直径值）。写反了要么切不动，要么余量留错。
> fix：`G71 U(切深) R(退刀)` / `G71 P Q U(X余量·直径) W(Z余量) F`。

**T04｜方位号与补偿方向冲突**
> why：外圆右手刀（T3）车外圆应配 G42。写 G41 刀尖偏到工件内侧，轮廓整体差一个刀尖半径。
> fix：外圆刀 T3 用 G42，内孔刀 T2 用 G41；先定方位号再选方向。

### 5.5 找错练习变异库（10 种，全部可检出）

漏 G50 限速 · G71 的 U 写半径值 · T 与刀补号不一致 · G76 牙高过深 · 刀补方向反 · G71 缺 Q 段 · 螺纹 F≠螺距 · 切断位置超总长 · 精车余量写 0 · X 写半径值

## 6. 测试与验收（v0.1 只写了"断言脚本"，太虚）

| 层 | 形态 | 数量 | 通过判据 |
|---|---|---|---|
| 规则语料 | `tests/corpus/<规则号>_bad.nc` + `_good.nc` | 50 × 2 = 100 | 反例必须被该规则命中；正例必须**不**被该规则命中（防假阳性） |
| 整程序 golden | 10 份模板 + 2 份综合件 | 12 | 校验 0 个 S/E；轨迹点与期望坐标差 < 0.01mm |
| 变异检出 | 10 种变异 | 10 | 每种至少被 1 条规则命中（逐条断言，不抽样） |
| 数据自检 | 螺纹表 / 材料表 | 1 | M30×1.5 小径 = 30−1.3×1.5 = 28.05；材料 vc_min < vc_max |
| 体积闸门 | 脚本断言 | 1 | `app.html` < 600 KB（见 §7） |
| 全模块冒烟 | 无头浏览器 | 10 面板 × 主路径 | 控制台无异常、无横向溢出、自动保存有效 |

规则语料的写法（每条形如）：

```js
// tests/corpus/S01_bad.nc  —— 毛坯 Φ50，写 X25 车外圆
O0001; G21 G99; T0101; M03 S800;
G00 X25 Z2; G01 Z-30 F0.2; G00 X100 Z100; M30;
// 期望：{rule:'S01', lv:'S', line:3}
```

**正例同样必须跑**——只测反例会训练出一个"见谁都报错"的校验器，假阳性比漏报更容易毁掉课堂信任。

## 7. 体积与性能预算（量化，来自实测）

铣削版 1.47 MB 的构成实测：

| 部分 | 铣削实测 | 占比 | 车削预算 | 措施 |
|---|---|---|---|---|
| 帮助配图 `help-img`（11 张 PNG base64） | **1158 KB** | **80.5%** | **≤100 KB** | 改内联 SVG 线稿，矢量几 KB 一张 |
| 主脚本 `app-js` | 198 KB | 13.8% | ≤250 KB | 50 规则 + 10 模板比铣削多 |
| 帮助正文 `help-md` | 31 KB | 2.2% | ≤40 KB | — |
| CSS + HTML 骨架 | ~85 KB | 5.8% | ≤30 KB | 只用设计令牌 |
| **合计** | **1473 KB** | — | **≤480 KB（硬闸门 600 KB）** | 发版脚本断言 |

结论：**体积问题不在代码，在帮助配图**。v0.1 说"体积会到 1 MB 级，靠测试守质量"是错的——1 MB 里有 80% 是截图，砍掉即可，不需要任何技术妥协。

## 9. 明确不做

| 不做 | 原因 |
|---|---|
| 3D 实体仿真 | 2D 剖面能讲清余量与过切，3D 成本高一个量级 |
| 机床通信（DNC） | 教学环境不接机床，涉安全 |
| 图纸图片识别 | 尺寸表链路更准更省时（§4.2 生成器页签）；识别留作远期辅助 |
| 宏程序完整求值 | 车削教材用得少，M4 后看需求 |
| 多系统（西门子/广数） | 与教材口径一致只做 FANUC，避免规则表翻倍 |
| 账号与云端同步 | 单机 local+导出足够；服务器只当静态托管 |

## 10. 已定的口径

1. **默认直径编程**，图样值直接写；轨迹图提供半径/直径切换并同步刻度标签。
2. **代码表按 FANUC 0i-T 标准建**，不绑教材页码；教材有独有写法（如 `,C_` 倒角格式、G71 Ⅱ 型讲法）时改表条目，模块结构不动。
3. **模板 10 个**，覆盖端面到综合件的完整工艺链。
4. **单文件 `app.html`**，零依赖零构建；体积由 §7 预算与脚本闸门守住，不靠人工自觉。
5. **移动端分两级**：只读面板（速查 / 解释 / 轨迹 / 帮助）手机完整可用；编辑与批改在 <900px 切"查看 + 粘贴"模式，隐藏快捷输入栏。断点沿用 1100 / 900 / 720 / 420。
